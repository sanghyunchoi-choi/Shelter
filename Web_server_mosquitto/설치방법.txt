# 스마트쉘터 CMS 설치 가이드 (Web_server_mosquitto)

## 접속 정보
- 대시보드 주소: `http://127.0.0.1:3000/` (또는 `http://localhost:3000/`)
- 로그인 계정: `smart` / `smart`

---

## 1단계. WSL2 설치

Windows PowerShell을 **관리자 권한**으로 실행 후:

```powershell
wsl --install
```

- 처음 설치하는 PC라면 이 명령 실행 후 **재부팅**이 필요합니다.
- 이미 WSL이 있다면 최신화만:
  ```powershell
  wsl --update
  ```
- 참고 문서: https://learn.microsoft.com/windows/wsl/install

---

## 2단계. Docker Desktop 설치

- 다운로드: https://www.docker.com/products/docker-desktop/
- 직접 다운로드 링크(Windows, Intel/AMD 64비트): https://desktop.docker.com/win/main/amd64/Docker%20Desktop%20Installer.exe
- 설치 중 **"Use WSL 2 instead of Hyper-V"** 옵션이 보이면 체크된 상태로 진행
- 설치 완료 후 Docker Desktop 실행 → 좌하단 아이콘이 **초록색 "Engine running"** 될 때까지 대기 (최초 실행 시 1~2분)

---

## 3단계. 프로젝트 폴더 이동

`Web_server_mosquitto` 폴더 전체를 새 컴퓨터로 복사합니다. 아래 구성이 전부 포함되어 있어야 합니다:

```
Web_server_mosquitto/
├─ Dockerfile
├─ Dockerfile.mosquitto
├─ docker-compose.yml
├─ mosquitto.conf
├─ package.json
├─ server.js
├─ install.bat
└─ public/
   └─ index.html (등)
```

> 경로에 한글/괄호가 섞여 있어도 빌드 자체는 대체로 문제없지만, 문제 생기면 가장 먼저 의심할 지점이니 가능하면 `C:\project\Web_server_mosquitto` 처럼 단순한 경로 사용을 권장합니다.

---

## 4단계. 실행

PowerShell에서 복사한 폴더로 이동 후:

```powershell
cd "복사한 폴더 경로"
docker compose up -d --build
```

- `--build`는 **최초 실행 시 반드시 필요**합니다 (이미지가 없는 새 컴퓨터이므로).
- 소스 수정 없이 재실행만 할 때는 `--build` 생략 가능:
  ```powershell
  docker compose up -d
  ```

## 5단계. 정상 기동 확인

```powershell
docker ps
```

아래 두 컨테이너가 **둘 다 `Up` 상태**이고, PORTS에 `0.0.0.0:포트->포트` 형태로 매핑이 보여야 정상입니다:

| 컨테이너 | 포트 |
|---|---|
| `shelter-mosquitto` | `0.0.0.0:1883->1883/tcp` |
| `shelter-web-local` | `0.0.0.0:3000->3000/tcp` |

브라우저에서 접속 확인:
```
http://127.0.0.1:3000/
```

## 문제 해결 (자주 발생하는 증상)

### ① `docker ps`에 shelter-web-local이 안 보임
```powershell
docker compose logs shelter-web
```
빌드/실행 에러 로그 확인.

### ② `port is already allocated` 에러
다른 프로그램/컨테이너가 이미 3000번(또는 1883번)을 쓰고 있는 경우.

```powershell
netstat -ano | findstr :3000
tasklist /FI "PID eq <위에서 나온 PID>"
```

- Docker 컨테이너가 범인이면:
  ```powershell
  docker ps --format "table {{.ID}}\t{{.Names}}\t{{.Ports}}"
  docker stop <충돌 컨테이너 이름>
  docker compose up -d
  ```
- 그래도 안 되면 강제로 재생성:
  ```powershell
  docker compose up -d --force-recreate shelter-web
  ```

### ③ PORTS 컬럼에 매핑이 빠지고 `3000/tcp`만 보임 (내부 포트만 열림)
호스트 포트 바인딩이 실패한 채로 컨테이너만 뜬 경우입니다. 충돌 컨테이너 정리 후:
```powershell
docker compose up -d --force-recreate shelter-web
docker ps
```
PORTS가 `0.0.0.0:3000->3000/tcp`로 바뀌었는지 재확인.

### ④ 여러 프로젝트를 한 PC에서 같이 쓰는 경우 (포트 겹침 회피)
`docker-compose.yml`에서 shelter-web 포트만 변경:
```yaml
  shelter-web:
    build: .
    container_name: shelter-web-local
    ports:
      - "3001:3000"   # 호스트 포트만 변경, 컨테이너 내부는 3000 유지
```
이 경우 접속 주소는 `http://127.0.0.1:3001/`

## 자주 쓰는 명령어 모음

| 목적 | 명령어 |
|---|---|
| 상태 확인 | `docker ps` |
| 전체 상태(종료된 것 포함) | `docker ps -a` |
| 로그 실시간 보기 | `docker compose logs -f shelter-web` |
| 재시작만 | `docker compose restart` |
| 완전 중지 | `docker compose down` |
| 소스 수정 후 재빌드 | `docker compose up -d --build --force-recreate` |
| 찌꺼기 정리 | `docker system prune -f` |
